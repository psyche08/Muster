# Native CLI validation — 2026-10-12

Release gate: **not passed; macOS and iOS publication is on hold** at the user's
request until Claude access recovers or another signed-in host is available.
This is a partial validation record, not a release or device-installation record.

## Environment and verified behavior

- Isolated `musterd` state and workspace under `/private/tmp/muster-cli-live`,
  with cloud, virtual networking and terminal integration disabled. Production
  state and installations were not replaced. The development daemon uses a
  software key; no signing/notarization claim follows from this run.
- Native Codex app-server `0.162.0-alpha.17.2` supplied by the installed Codex
  desktop app. No Node runtime or separately installed Orca service was used.
- A real Codex turn read `readme.txt`, created `codex-verified.txt` containing
  exactly `MUSTER_CODEX_LIVE_OK`, and rendered a Chinese Markdown heading, table,
  code block, completed command group and final turn status in native macOS UI.
- A second turn sent from the native composer used `apply_patch` to replace the
  second line of `readme.txt`. The real patch rendered its file, hunk, line
  numbers and +1/-1 totals. An extra empty “Changes” card was found and fixed:
  Rust now passes the unified patch without prepending its display label.
- A successful send initially left text in the composer. Temporary diagnostics
  established that AppKit echoed the unchanged text after sending, generating
  a false edit revision. The binding now ignores identical values. Diagnostics
  were removed; subsequent real sends visibly cleared the composer on receipt.
- Restarted daemon and client preserved history and patches. A new turn with
  the same compatible Codex version recalled the original file name and exact
  marker and returned `RESUME_OK`.
- `MusterDev` now uses the configured daemon directory for its core/cache state,
  so `MUSTER_DIR` isolates both socket and client state during validation.

## Checks and limitations

- Rust agent/app-core libraries: 231 tests passed, 5 ignored. One additional
  existing test, `cloud::tests::credentials_follow_the_profile_paths_and_expiry`,
  failed on the signed-in Mac because its missing-directory assertion also
  falls back to the real Keychain; it was excluded from the follow-up run.
  Login state was not modified. The new diff regression test passed.
- macOS `MusterDev` build and iOS simulator `MusterUI` target compilation passed.
  iOS compilation is not physical iPhone rendering or end-to-end verification.
- Claude was signed in, but real inference returned an account-on-hold error.
  Claude success, streaming, tools, approval and resume remain unverified.
- A restart with a different PATH selected native Codex `0.146.0`; its turn
  failed because the configured model requires a newer CLI. Repeating the
  independent context check with `0.162.0-alpha.17.2` succeeded. Packaged-host
  CLI selection/version compatibility still needs validation.
- Keeping the development client open across daemon replacement produced a
  closed-connection send error. Reopening the client restored access. History
  refresh after subsequent sends also needs further investigation; do not claim
  seamless automatic reconnect or live updates across daemon restart.
- The attempted `sleep 45` turn completed before a stop was exercised. Real
  interruption and interactive approval responses remain open gates.
- No release version bump, signing, notarization, production installation,
  macOS update publication, iOS OTA publication or TestFlight upload occurred.
